Préparer son poste

Trois programmes doivent s'entendre sur votre machine. Docker fait tourner des conteneurs. minikube s'en sert pour fabriquer un cluster Kubernetes complet, rangé tout entier dans un seul conteneur. Et kubectl est l'outil avec lequel vous parlerez à ce cluster pendant tout le cours.

Démarrer un cluster

Le cluster du cours reçoit deux processeurs et quatre gigaoctets de mémoire. C'est assez pour tout ce que nous ferons jusqu'à la partie VI, et ça laisse de la place à votre navigateur.

Pilote. La manière dont minikube crée le nœud : un conteneur (docker, podman) ou une machine virtuelle (kvm2, virtualbox).minikube.sigs.k8s.io/docs/drivers
$ minikube start --driver=docker --cpus=2 --memory=4g
* minikube v1.39.0 sur Ubuntu 26.04 * Utilisation du pilote docker basé sur la configuration de l'utilisateur * Préparation de Kubernetes v1.37.0 sur containerd 2.3.4... * Terminé ! kubectl est maintenant configuré pour utiliser "minikube" cluster et espace de noms "default" par défaut.

Relisez la ligne surlignée. À l'intérieur du nœud, ce n'est pas Docker qui lancera vos conteneurs, c'est containerd. Docker ne sert ici qu'à fabriquer la « machine » qui joue le rôle de nœud. Cette distinction paraît byzantine le premier jour ; elle devient évidente au chapitre 11, quand on démonte la pile des runtimes.

Avec Podman. minikube accepte --driver=podman, mais ce pilote reste marqué expérimental. L'annexe B donne la configuration rootless qui fonctionne.

Un premier déploiement pour vérifier

$ kubectl create deployment bonjour --image=nginx:1.29-alpine $ kubectl expose deployment bonjour --type=NodePort --port=80 $ curl -s $(minikube service bonjour --url) | grep title
deployment.apps/bonjour created service/bonjour exposed <title>Welcome to nginx!</title>
NodePort. Port ouvert sur chaque nœud, entre 30000 et 32767, qui redirige vers le Service.1[1] kubernetes.io/docs/concepts/services-networking/service

Si curl ne renvoie rien du premier coup, relancez-le une seconde plus tard : kube-proxy n'a pas toujours fini de poser ses règles quand le Service vient d'être créé.
